# 知语：Windows 本地聊天分析助手

## 启动

解压 `JevLocalAssistant-windows.zip`，保留整个文件夹，双击 `JevLocalAssistant.exe`。这是 Qt 原生桌面窗口，不需要浏览器，也不需要为主程序安装 Python。

首次打开会显示设置与诊断。缺少模型或数据源时仍能启动、管理已保存的档案。关闭主窗口会取消任务并退出，没有后台托盘。

## 准备 CipherTalk

使用 [CipherTalk-FM-Edition](https://github.com/LFM097384/CipherTalk-FM-Edition) 中独立的 `CipherTalk-CLI`。接口基线是提交 `d3aaacb0d37ad44d45c6502b43ab0405aa2769ad`；不要假设 npm 上同名包等同于该分支。

1. 按该项目说明安装 Node.js 22.12+，准备 CLI 及其原生组件。
2. 在 CipherTalk 中完成当前账号的数据目录、授权和数据库配置。数据库凭据由 CipherTalk 管理，本工具不获取或展示。
3. 在本工具设置中选择 `node.exe`、构建后的 CLI 入口 `bin/miyu.js`，点击检查。
4. 配置必须包含当前微信账号 wxid，否则工具会拒绝连接以避免串档。

CLI 通过 `mcp serve` 启动。工具会验证 MCP 能力和数据库连接；授权失败、缺少原生库或未连接数据库不会被当成成功。该分支存在联网授权检查，并非严格离线软件。

## 准备 Laya（独立运行环境）

主程序不捆绑 PyTorch 或模型权重。开发者可在项目根目录执行以下 PowerShell 命令，所有 Python 命令前设置 UTF-8：

```powershell
$env:PYTHONUTF8 = '1'
uv venv .venv-laya
uv pip install --python .venv-laya/Scripts/python.exe laya==0.3.5
.venv-laya/Scripts/python.exe -m scripts.prepare_laya_model .venv-laya/model
```

下载脚本仅在明确执行时联网，下载固定提交的多语言模型并生成 SHA-256 清单。运行应用时不下载；加载前校验清单和文件。将 `.venv-laya/Scripts/python.exe` 和 `.venv-laya/model` 的绝对路径填入设置。

模型来源：`convaiinnovations/laya` 的 `multilingual` 子目录，提交 `1c5edc17a7acd8701df6fc341c0d179f1c62c982`；SDK 固定 `laya==0.3.5`。SDK 输入为 `predict(state, questions)`，回答在 `answers` 中；SDK score 0–3 映射为现有契约 1–4。

桌面分析会复用 Laya 进程，只在首次使用时加载并校验模型。首次等待上限为 120 秒，热调用上限为 30 秒。模型驻留内存直到关闭应用；取消正在进行的推理、响应异常或修改模型路径时会销毁进程，下次重新加载。单独的依赖诊断仍使用一次性进程。加载成功不代表分类准确率通过；这些分数尚未按本项目的中文聊天场景校准。

复现本次验证环境可用 `runtime/laya_decision/requirements-validated.txt` 安装锁定的完整依赖。运行合成案例评估：

```powershell
$env:PYTHONUTF8 = '1'
$env:LAYA_MODEL_PATH = (Resolve-Path '.venv-laya/model').Path
.venv-laya/Scripts/python.exe -m scripts.evaluate_laya
```

本次意图分类匹配率较低，具体见 `验收结果.md`，不要把模型运行成功理解为效果合格。

设置中的“自动查找已准备的依赖”只检查软件附近的约定目录并填充空项，不下载、不覆盖已填写路径。直接从本项目 `dist` 运行时，可以找到项目根目录下已准备好的 `.venv-laya`。

## 配置回复模型

设置填写 OpenAI 兼容基础地址及模型名，例如服务商明确提供的 `/v1` 地址。程序会追加 `/chat/completions`，不自动修改模型名。云端只接受 HTTPS，本机可使用 HTTP。不会自动跟随重定向。

密钥只从环境变量读取。设置中填写变量名称（默认 `OPENAI_API_KEY`），通过 Windows“编辑账户的环境变量”配置具体值，然后重新启动软件。不要把密钥粘贴到地址、档案、命令参数或聊天记录中。本机无鉴权模型接口可不设密钥。

程序不内置共享密钥，不自动切换到其他服务商，不进行后台遥测或更新检查。网络代理不从环境自动继承；请使用本机可直达的服务地址。

## 日常使用

1. 刷新单聊会话，选择联系人。默认加载最近 50 条消息，可继续加载。
2. 默认分析最近 6 条文本；也可按 Ctrl/Shift 选择消息，并切换范围。回复分析最多取最后 6 条文本，预览展示实际选择。
3. 填写本轮要求，点击“预览并分析”。检查脱敏后的消息、档案与记忆，可取消勾选本次不需要的记忆。
4. 默认确认后依次执行 Laya 和回复生成；也可事先选择“仅生成回复（跳过本地判断）”，直接使用已确认的上下文。Laya 不可用时仍可单独选择仅生成回复。
5. 候选文本可在右侧直接修改后复制，再手动发送。软件不操作微信输入框。

模型只推测可能意图。未知方向消息不作为确定意图的依据，非文本消息只展示占位。候选不标排名或成功概率。取消、换会话或重新分析后，旧任务结果不会覆盖新结果。

## 档案与记忆

- 选择会话后打开“联系人与记忆”，填写关系、备注、表达偏好；离线时也能查看已有档案。
- 选择最多 50 条文本消息，点击“提取记忆候选”。确认预览后会调用生成接口。
- 检查候选的原文依据与已有记忆。无冲突可新增；有冲突需选择旧记忆并明确替换；临时情绪、无证据事实应拒绝。
- 只有用户确认的候选会持久化。可修改内容、固定优先引用或删除；原证据不随编辑改写。
- 同主题阻止重复新增。跨主题的语义冲突由用户在并排列表中核对，不宣称自动识别所有矛盾。

## 数据与故障

数据位于 `%LOCALAPPDATA%/JevLocalAssistant`：`settings.json` 保存非密钥配置；`assistant.sqlite3` 保存档案、确认记忆及脱敏证据短摘录。完整聊天历史不复制到该目录，分析结果仅在内存中。备份、迁移请先关闭程序。

上游原始消息仅为本次显示和分析暂存在内存。自动脱敏覆盖常见手机号、邮箱、银行卡/证件号和令牌模式，仍需在发送预览中人工检查其他敏感信息。

发生问题时先检查三个组件：CipherTalk 是否能连接数据库、Laya 是否有本地模型、生成接口是否有有效模型和环境变量。界面不会展示上游原始错误正文，避免泄露聊天或凭据。

也可执行 `JevLocalAssistant.exe --diagnose-output diagnosis.json`，检查已配置的 CipherTalk 与 Laya，并输出不含密钥和聊天正文的诊断结果（UTF-8）。该检查会启动外部组件，CipherTalk 的授权检查可能联网。

## 开发、测试与打包

```powershell
$env:PYTHONUTF8 = '1'
uv venv .venv
uv pip install --python .venv/Scripts/python.exe -r requirements-dev.txt
.venv/Scripts/python.exe launch_desktop.py
.venv/Scripts/python.exe -m pytest -q
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-desktop.ps1
```

交付目录为 `dist/JevLocalAssistant/`，压缩包为 `dist/JevLocalAssistant-windows.zip`。打包不包含 CipherTalk、数据库、凭据及模型权重。

Qt 使用动态链接的 PySide6（LGPLv3 等许可，详见随包第三方许可）；不额外使用商业 Qt 模块。应用尚未签名，首次启动可能出现 Windows 发布者提示。
