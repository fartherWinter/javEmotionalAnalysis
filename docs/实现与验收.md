# 实现与验收记录

## 结构

- `desktop/`：Qt Widgets 界面、异步后台任务、stdio MCP、OpenAI 兼容生成客户端、SQLite 档案与确认式记忆。
- `runtime/laya_decision/`：兼容原 JSONL 契约的独立模型进程，固定 SDK 及本地模型清单。
- `tests/`：数据隔离、证据、错误处理、真实 stdio 测试服务、Qt 桌面测试。
- `scripts/`：独立模型准备、效果评估及 EXE/ZIP 打包。

外部数据与模型网络调用仅在用户发起操作时执行。无 Web 页面、HTTP 服务、自动发送、实时读屏或群聊推断。

## 对既有方案的修正

原始方案中的 Router 单参数调用与公开 SDK 不兼容。实现改为 `laya==0.3.5` 的 `load(local_path).predict(state, questions)`，明确加载多语言模型。choice 使用 criteria，score 使用等级列表，结果从 answers 提取，SDK 0–3 级映射到契约 1–4 级。

Laya fallback 只是不可用标记，绝不作为中性情绪的判断。缺失字段不会被填充成有效推理。模型分数未进行项目场景校准。

0.2.0 将意图单独作为一次推理：输入为对方最新消息和此前的对话，题目与选项解释使用中文，类别键保持契约定义。情绪和回复策略仍使用完整状态。对外 `predict/check` 字段不变。

桌面窗口持有一个 LayaSession，JSONL 请求以锁串行化并校验请求 ID。正常请求后保留模型；取消、超时或协议错误会销毁流，避免上一条响应被下一次请求消费。退出后台任务循环前清理空闲模型进程。只改生成接口设置不会重新加载模型。

CipherTalk 的 list_sessions 显示名可能只是账号 ID，因此额外调用 list_contacts 映射联系人名称。身份隔离仍使用账号与 sessionId；昵称不能决定数据归属。

## 验收边界

自动测试中的 CipherTalk 使用真正的 MCP stdio 协议测试服务，验证握手与分页，但不等同于读取真实微信数据。生成接口通过 HTTP 替身验证响应及失败行为，不等同于真实服务商调用。

真实端到端验收必须另行确认：CipherTalk 有可用的本地数据库与授权、配置有效的生成接口及密钥，然后在界面完成一次真实分析。缺少这些配置时，不能宣称端到端验收通过。

模型评估集是开发时编写的 30 条合成中文案例与预期标签，并非独立人工评审数据或生产准确率。评估脚本必须记录 fallback 数量，不得以回退当正常判断。

详细实测结果见 `验收结果.md`。
